## 1. Overview

The documented translation command destroyed the page it was meant to
regenerate: with no `ANTHROPIC_API_KEY` it silently swapped in a placeholder
client and wrote its one-line output over the topic's published Japanese page.
It now refuses instead, and the stub is reachable only when asked for.

**Highlights:**

1. A keyless `research:translate-report` exits non-zero and writes nothing.
2. The refusal names the variable, the page, `--estimate` and `--fixture`.
3. The same fork existed in both translation runners; it is now one module.

## 2. Motivation

Nothing between the missing key and the overwritten page said anything was
wrong. The guard that looks like it would catch this is defeated by design: the
fixture stub echoes every number it finds so the domain's numeric-preservation
check reports no miss, and the only other signal was node's routine `.env not
found` line. One page has already been lost this way and repaired by hand —
`foundation-models.insights.ja.md` still carries
`provenance: hand-authored-translation` for exactly that reason. The observability
policy names this shape directly: a degraded run rendering as a successful one.

## 3. Changes

### 3-1. Refuse the keyless translation instead of stubbing ([14fe454](https://github.com/qmu/research/commit/14fe454))

Client selection moved out of both runners into
`research/translation-client.ts`, which throws when the key is absent unless the
caller passed `allowFixture` — wired to a new `--fixture` flag on the entrypoint,
matching the repository's existing fixture vocabulary. `--estimate` returns before
any client is built, so pricing stays keyless.

## 4. Outcome

The command that regenerates a published article can no longer destroy it by
being run without a credential. Seven new tests pin the refusal, the empty-key
case, the message's contents, and the untouched page bytes; CLAUDE.md's Deploy
section was corrected in the same change.

## 5. Concerns

### The insights-stage sibling was fixed without a ticket asking

- **Severity:** low
- **Description:** `translate-runner.ts` carried a byte-identical copy of the key-fork and was changed in the same commit, one call site beyond the ticket's Key Files (see [14fe454](https://github.com/qmu/research/commit/14fe454) in `packages/tech/src/research/translate-runner.ts`)
- **How to Fix:** nothing to undo — but the reviewer should confirm the widening was wanted, since the alternative was leaving the same defect reachable through `npm run research -- <topic> --real`

## 6. Successful Development Patterns

- Running the destructive path once behind the new opt-in, then restoring the
  file with a targeted checkout, proved both halves of the change — that the stub
  is still reachable and exactly what the refusal prevents.
- Reading `planPipeline` before widening the refusal answered "will this break
  CI?" from the plan itself rather than from running CI and hoping.
