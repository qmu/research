## 2. Motivation

Recorded here so the grouping is not re-litigated.

The OCR comparison does not currently discriminate: on standard images and PDFs today's OCR-capable models all score near-perfect, so the comparison separates nobody — "no actual model is examined". The fix is a corpus of **generated** hard inputs (real hard documents are unusable for licensing, privacy and reproducibility reasons), which has the useful side effect that ground truth is known **exactly**.

The image-generation ticket then defines a new **readability** metric whose judge is **not hardcoded**: it is whatever the OCR comparison currently ranks best, read from the latest OCR frame's emitted "best OCR model" output. That is a direct data dependency in one direction — the OCR ticket must emit that output before the readability metric has a judge to call. Splitting them across two PRs would produce a PR that cannot merge.

## 8. Handoff — what remains and where to start

**State:** claimed on `work-20260801-120905`; both tickets still in `.workaholic/tickets/todo/a-qmu-jp/`. Zero implementation commits.

**Take it over** with `claim.sh resume batch-20260801120905`, which rebuilds the worktree at this branch tip. Both tickets carry full Implementation Steps and Quality Gates — read those, not this summary, before building.

**Order is forced by the data dependency:**

1. **`20260721120004` (OCR) first.** Build the deterministic generator for the three owner-named hard classes — low-quality/"jaggy" (low-resolution rasterization, compression and scan-like degradation), high character density (dense small-type pages), and complex structure (tables containing nested data structures). Generation is deterministic and the corpus (or its seed + generator) is committed and **versioned**, because a periodic comparison needs a stable corpus. Ground truth is exact because the corpus is generated.
2. **Emit "best OCR model"** as a defined output of the latest frame. This is the interface the second ticket consumes, and it is an explicit item in `20260721120004`'s Quality Gate.
3. **`20260721120005` (readability) second.** Add the text-document prompt class (pitch-deck slide / infographic with known intended text) and the readability metric scored by OCR read-back, with the judge **read from** step 2's output — never a hardcoded model name.

**The discrimination criterion is the real bar.** A hard class where every model still scores ~100% is **not** a finding and must be flagged as non-discriminating rather than published as a result. That is the whole point of the OCR ticket, and it is the criterion most easily lost while building the generator.

**Verification** is per-package with bare exit codes, run separately, never through `make test` / `make lint`: `( cd packages/tech && npm test )`, `( cd packages/tech && npm run build )`, `( cd packages/tech && npm run lint )`.

**One trap worth carrying over**, learned on another unit in the same run: a renderer change to a topic that has a measured history frame is invisible to both the published page and `make drift`, because the current page is composed from the frame rather than the keyless render. Do not read a green `make drift` as evidence that a new report section works — cover it with unit tests and exercise the renderer directly.
