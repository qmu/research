## 1. Overview

The documentation site now separates its two languages by URL prefix — `/en/…`
and `/ja/…` — instead of by sidebar group, so the VitePress theme renders its
language switcher in the header beside the light/dark toggle. No Markdown file
moved.

**Highlights:**

1. `/en/<base>` and `/ja/<base>` mirror, so the switcher lands on the same study.
2. One function feeds both the rewrites and every link, so `make build` guards it.
3. `/` redirects to `/en/`; English-only project docs keep root routes.

## 2. Motivation

The languages were split only inside the sidebar: a reader chose one by picking a
navigation group, and both shared a single URL space. That is the one shape a
header switcher cannot work in — VitePress reads the current locale from the
leading path segment, so with no prefix there is nothing to switch. The obvious
fix, moving the files under `docs/en/` and `docs/ja/`, would have rewritten every
runner output path, publish slug and history frame location in `packages/tech`,
so the on-disk layout was left alone and the mapping made explicit instead.

## 3. Changes

### 3-1. Serve the docs site as /en and /ja locales ([c678841](https://github.com/qmu/research/commit/c678841))

Declares the two VitePress locales, maps the on-disk layout onto their routes
with `docsRewriteTarget`, and generates every in-repo link from that same
function. English insights drafts and three superseded Japanese pages are
excluded so each route has one page; `docs/public/index.html` redirects `/`.

### 3-2. Regenerate the docs pages onto the locale routes ([ad29b3c](https://github.com/qmu/research/commit/ad29b3c))

Rewrites the generated indexes and the Japanese current pages against the new
routes, including each article's past-survey links, which now name their dated
frame exactly like the English one.

## 4. Outcome

English reads under `/en/` and Japanese under `/ja/`, each with its own sidebar,
title and `lang` attribute, and the header switcher moves between them.
Japanese URLs no longer expose `.insights.ja`. Every gate CI runs passes locally
except `make a11y`, which this host cannot run.

## 5. Concerns

### Every existing site URL changed

- **Severity:** low
- **Description:** `/research-reports/<page>` became `/en/<page>` and `/ja/<page>`, so every earlier URL 404s; nothing external links to them — staging is `noindex` and the articles are published on qmu.co.jp (see [c678841](https://github.com/qmu/research/commit/c678841) in `docs/.vitepress/config.ts`)
- **How to Fix:** Leave as is unless a stale link is reported; a redirect map can go in `docs/public/`.

### qmu-co-jp keeps orphan `.ja` frame copies

- **Severity:** moderate
- **Description:** Dated Japanese surveys now copy to qmu-co-jp without the `.ja` suffix, because the in-article link and the copy destination must name one file; the copies published under the old name are orphaned and `scripts/publish-ledger.tsv` still records them (see [c678841](https://github.com/qmu/research/commit/c678841) in `packages/tech/src/research/domain/site.ts`)
- **How to Fix:** The ticket payload now asks qmu-co-jp to delete them; prune the ledger rows once confirmed.

### `make a11y` is unrunnable on this host

- **Severity:** low
- **Description:** Port 4173 is held by an unrelated rootless container and the cached Puppeteer Chrome is the wrong architecture, so the accessibility gate never ran against the new routes (see [c678841](https://github.com/qmu/research/commit/c678841) in `docs/.pa11yci`)
- **How to Fix:** Read the `check` job's `make a11y` step on this branch before merging, rather than treating the local gap as a pass.

### `.data.json` links stay dead in the built site

- **Severity:** low
- **Description:** VitePress copies no non-Markdown file out of `docs/`, so the history indexes' artifact links 404 — as they did before, now under `/en/history/…` (see [ad29b3c](https://github.com/qmu/research/commit/ad29b3c) in `docs/research-reports/history.md`)
- **How to Fix:** Point them at stable raw.githubusercontent.com URLs; tracked as `json-artifact-link-resolution-deferred`.

## 6. Successful Development Patterns

- Deriving routes and links from one exported function turned the dead-link
  checker into the migration's guard — `make build` fails when the two disagree.
- Reading the VitePress dist bundle settled two facts its docs omit (`rewrites`
  accepts a function; `relativePath` is the rewritten path), which is what made a
  zero-file-move migration possible.
