## 1. Overview

On the easy v1 corpus every model scores near-perfect, so the comparison
separates nothing. This branch generates a corpus that is hard on purpose, plus
the gate that refuses to publish a class that still separated nothing.

**Highlights:**

1. Three hard classes — degraded scan, high density, nested table — deterministic from a versioned manifest
2. Ground truth and pixels come from one page description, so they cannot drift apart
3. A class that does not separate the models is reported as non-discriminating, never as a ranking

## 2. Motivation

A periodic comparison whose subjects all read ~100% tells a reader nothing about
which OCR model to use — the owner's words were that "no actual model is
examined". Real hard documents cannot be used for licensing, privacy and
reproducibility reasons, and generating the corpus turns that constraint into an
advantage: what is generated has exact ground truth, so strict scoring becomes
possible rather than approximate.

## 3. Changes

### 3-1. Make the OCR comparison discriminate, using generated hard inputs ([abe8844](https://github.com/qmu/research/commit/abe8844))

Adds the deterministic generator, the scan-degradation chain, the pinned corpus
manifest with its drift test, and the discrimination module that decides whether
a class separated the models and which model won. The v1 renderer's primitives
move to `raster.ts` unchanged so both corpora share them.

## 4. Outcome

Nine hard pages generate byte-identically from `(version, class, index)`, and the
committed manifest fails the suite if that stops being true. Running the
comparison against them is the handoff.

## 5. Concerns

- **Severity:** moderate
- **Description:** `scan-branch-safety.sh` returns `block` at `override` severity — 2087 added lines against a 500-line per-commit bar — because the raster extraction, the degradation model, the corpus generator and the discrimination module landed together (see [abe8844](https://github.com/qmu/research/commit/abe8844))
- **How to Fix:** Split the next increment into one commit per module as it is written; this one cannot be split now without a force-push, which an unattended run must not do

### The high-density class may not be hard at all

- **Severity:** moderate
- **Description:** It renders clean half-scale type with no degradation, and a modern vision model may read it perfectly, in which case the class contributes nothing to separation (see [abe8844](https://github.com/qmu/research/commit/abe8844) in `packages/tech/src/ocr-comparison/domain/hard-corpus.ts`)
- **How to Fix:** Let the first real trial decide it — the discrimination gate already reports the class as non-discriminating rather than publishing noise — then raise its density or add mild degradation and bump `HARD_CORPUS_VERSION`

### Nested structure is carried by indentation, not ruled cells

- **Severity:** low
- **Description:** The nested-table class conveys grouping through column offsets alone; ruled cells would be the stronger structural signal and closer to the documents the class stands in for (see [abe8844](https://github.com/qmu/research/commit/abe8844) in `packages/tech/src/ocr-comparison/domain/hard-corpus.ts`)
- **How to Fix:** Add vertical rules to the `rules` list when the class is next revised, under a new corpus version

## 6. Successful Development Patterns

- Making ground truth a *derivation* of the page description rather than a parallel authored string removes the drift failure mode by construction — the test pins it, but the design is what holds it.
- Extracting shared primitives with the old constant as the new parameter's default kept a byte-frozen fixture provably intact through a refactor, in one step and with a hash-by-hash proof.
- A page-overflow assertion written alongside the generator caught a clipped ground-truth cell on its first run — cheap invariants pay immediately when a generator is the thing under test.
