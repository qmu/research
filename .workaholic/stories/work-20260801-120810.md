## 1. Overview

This branch closes the history-frame series-nav dead link that has been blocking the VitePress build for the recovered topics — but **not** by either fix option the ticket proposed, because both were stale by the time it was driven.

The ticket's Option B (a `stripSurveyBlocks` pure function applied at archive time) had **already landed on `main`**: added in `a55af1a`, reverted in `e0baa92` to pause the ship, and then **reapplied in `2a22bfc`**, which is an ancestor of `origin/main`. Option A (a scoped `ignoreDeadLinks` in the VitePress config) was deliberately **not** taken — with the renderer already fixed it buys nothing, and it would exempt the entire class of in-frame links, suppressing detection of exactly the next stale frame.

What was genuinely missing is the item the ticket's own `## Policies` section already demanded: a regression assertion over the **committed** frames. It was added, and **it found a real violation on `main` on its first run**.

**Highlights:**

1. Added `packages/tech/src/research/history-frames.test.ts`, asserting that every committed `.md` under `docs/research-reports/history/` carries no `](./history/` link and neither survey-series block (推移 / 過去の調査).
2. Exported `TREND_LABEL` / `RELATED_LABEL` from `domain/current-article.ts` so the guard asserts against the renderer's own constants and cannot go vacuous if a label is renamed.
3. The guard includes a third assertion that the walk found at least one frame, so it cannot pass by checking nothing.
4. **The guard caught a real stale frame:** `docs/research-reports/history/token-metering/2026-07-17T03-02-34-699Z/token-metering-comparison.md` carried the 推移 block. It was archived before the strip fix landed, and was brought into conformance by running the repo's own `stripSurveyBlocks` over it — not by hand-editing.

## 2. Motivation

The archive-time strip is a **write-path** guarantee with no read-path counterpart. It governs only frames written after it landed, so every frame archived earlier stayed silently non-conformant with the repo's stated archive contract, and nothing reported the divergence. The token-metering frame sat in that state across several drives.

That gap is not academic: the three recovery branches (deep-research, speech, computer-use) carry frames archived **before** `2a22bfc`, and theirs carry the blocks *with* the links. When those branches catch up on `main`, this guard is what fails — by name, in `npm test`, well before an opaque VitePress dead-link error at `make build`.

## 6. Concerns

- **The three recovery branches will now fail this guard.** That is the intended catch, not a regression. On each branch the fix is to re-archive the frame, or run `stripSurveyBlocks` over its markdown copies as was done here. Expect deep-research, speech, and computer-use to need this before they can merge.
- **Option A remains available but is not recommended.** If a future in-frame link genuinely must be exempted, scope the regex to that link rather than to the `/history/<topic>/<frame>/<page>` shape, which is the whole class.
- **The guard reads the working tree, not the diff.** A frame added by a merge from another branch is caught on the next test run, which is the right moment, but it means a red `npm test` may be attributable to a merge rather than to the branch's own commits.

## 7. Successful Development Patterns

- **A write-path normalization wants a committed-state assertion beside it.** The strip fix was correct and still left the repo divergent from its own contract. Pairing "we normalize on write" with "we assert what is committed" is what closed the gap, and it found a real instance immediately.
- **Sharing constants between the producer and the guard.** Exporting the labels rather than re-literalizing them in the test means a rename cannot quietly make the assertion vacuous.
- **Assert the fixture set is non-empty.** A directory-walking guard that finds nothing passes. The third assertion makes that failure mode visible.
- **Normalize with the repo's own function, never by hand.** The stale frame was fixed by running `stripSurveyBlocks` over it, so the committed bytes are exactly what the archive path produces.
