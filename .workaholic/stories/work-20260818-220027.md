## 1. Overview

Dependabot's weekly updates now arrive as one grouped pull request per manifest
instead of one per dependency, and `/docs` is configured for the first time. The
one bump that could not land — TypeScript 7 — is filed as a ticket rather than
left as an open PR.

**Highlights:**

1. Four manifests (`packages/tech`, `packages/industry`, `docs`, github-actions), each with a minor/patch group
2. Major bumps stay ungrouped, so a judgment call is never bundled into a routine batch
3. The TypeScript 7 migration is a ticket with its blocker named and a startability check as step 1

## 2. Motivation

The 2026-08-11 week opened eleven Dependabot PRs (#89–#99). They shared three
lockfiles, so merging any one made its siblings conflict, and each carried its own
full CI run — the cost was entirely in the count, since every change was a routine
minor or patch bump. `/docs` had no configuration at all and was reachable only by
Dependabot's security updates, which need none.

## 3. Changes

### 3-1. Group Dependabot's weekly bumps per manifest ([fce81aa](https://github.com/qmu/research/commit/fce81aa))

Adds a `groups` block scoped to `update-types: [minor, patch]` for each of the four
update entries and adds the missing `/docs` npm entry, with the reasoning recorded
as comments in the file. Files the TypeScript 7 migration as a todo ticket carrying
the exact peer-range blocker (`typescript-eslint` declares `typescript: ">=4.8.4 <6.1.0"`).

## 4. Outcome

A normal week now produces at most four Dependabot PRs instead of roughly eleven,
and the one bump that needs a decision still arrives alone. The 18 pull requests
open before this branch are all resolved: 16 merged, #96 closed against the new
ticket.

## 5. Concerns

### Grouping is only proven by Dependabot's next weekly run

- **Severity:** low
- **Description:** The config parses and follows the documented `groups` schema, but nothing in CI exercises it — the first real evidence is the next weekly update batch (see [fce81aa](https://github.com/qmu/research/commit/fce81aa) in `.github/dependabot.yml`)
- **How to Fix:** Check the next weekly batch: expect one PR per manifest for minor/patch, and confirm `/docs` is proposed at all

## 6. Successful Development Patterns

- Grouping and the major-update exclusion are one mechanism, not two: scoping the group to `update-types: [minor, patch]` is exactly what leaves majors on their own, so a #96-style unmergeable bump cannot take a whole batch red with it.
