## 2. Motivation

On 2026-08-13 one `[Implement]` session opened two handoff PRs on branches
carrying no work and announced both as delivered. Every surface reported
success — PR open, Slack post sent, claim released — so nothing but a human
reading the diff against the post could tell. The ticket exists because that
class of failure is silent by construction, and it asked for the mechanism to be
found before a guard was designed for it.

## 5. Concerns

### The push between commit and PR is owned by no script

- **Severity:** moderate
- **Description:** `/report`'s Phase 4 push is prose in the skill; `commit.sh` contains no `git push`, and `create-or-update.sh` reads nothing about the remote before opening the PR — so nothing detects a story commit that never left the container (see [f52423a](https://github.com/qmu/research/commit/f52423a) in `.workaholic/tickets/todo/20260813035140-handoff-pr-opened-on-a-branch-carrying-no-work.md`)
- **How to Fix:** In `qmu/workaholic`, have `create-or-update.sh` fetch and compare `git rev-parse HEAD` against `git rev-parse origin/<branch>` before creating the PR. `archive.sh` already self-pushes, which closes the same gap for ticket archives only.

- **Severity:** moderate
- **Description:** A grep over the whole 1.0.183 plugin tree for `empty_head` / `no_work_commit` / coordination-commit counting finds nothing; the rule "an unpublished handoff is not a handoff" exists only as prose in `skills/drive/reference/routing.md:201` (see [f52423a](https://github.com/qmu/research/commit/f52423a))
