## 1. Overview

This branch commits the Claude Code Web bootstrap so the repository's two newly
created cloud routines (`[Propose] research`, `[Implement] research`) load the
workaholic plugin when they fire instead of no-opping at their precondition.

**Highlights:**

1. `.claude/hooks/session-start.sh` — byte-for-byte canonical copy from workaholic 1.0.166
2. `.claude/settings.json` — `SessionStart` (matcher `startup`, timeout 120), `enabledPlugins`, `extraKnownMarketplaces`
3. `check-bootstrap.sh` now returns `ok: true` on all checks

## 2. Motivation

`/setup-routines` (2026-08-13) created the two hourly routines via
`RemoteTrigger`, and the same run's `check-bootstrap.sh` reported the repository
unbootstrapped on all four counts. A cloud routine runs in a fresh container
where `enabledPlugins` alone installs nothing — a configured routine and a
working routine are different states, and this commit is what separates them.

## 3. Changes

### 3-1. Cloud routines fire on schedule but load no plugin — commit the Claude Code Web bootstrap ([44ecb7e](https://github.com/qmu/research/commit/44ecb7e))

Installs the plugin's canonical `SessionStart` bootstrap hook and registers it
in a new `.claude/settings.json`, so ephemeral cloud sessions load the plugin
before the routine prompt runs. `.claude/git-identities` is deliberately
excluded on the developer's explicit instruction.

## 4. Outcome

`check-bootstrap.sh` against the branch returns `ok: true` with empty
`problems`; once merged, the next `:15` / `:30` fires run with the plugin
loaded.

## 5. Concerns

### Cloud [Implement] cannot claim personally-assigned tickets

- **Severity:** moderate
- **Description:** `.claude/git-identities` was deliberately not committed (developer instruction, 2026-08-13: resolve identity on demand, not from a file), so a cloud session keeps the container's default git identity and the developer's own `[Implement]` routine skips tickets assigned to them (see [44ecb7e](https://github.com/qmu/research/commit/44ecb7e) in `.claude/hooks/session-start.sh`)
- **How to Fix:** Propose on-demand identity resolution (e.g. map the `gh api user` login at session start without a committed file) to qmu/workaholic via `/fb`
