## 1. Overview

The `.workaholic/` ledger indexes now merge by union instead of by conflict, and a
CI check makes the union's silence safe. Writing the check first exposed drift that
was already there: 12 story files and one feedback record were missing from their
indexes.

**Highlights:**

1. `.gitattributes`: `merge=union` on `.workaholic/**/index.md` — git's built-in driver, no per-clone config
2. `make ledger` in CI: every entry must point at a file that exists, every file listed exactly once
3. The 13 missing entries are restored and the stories index is back in date order

## 2. Motivation

Every desk appends its line at the top of the same index, so two branches that each
record their own work collide on a file where both sides are right. Clearing one
week of pull requests cost seven identical hand-resolutions, none of them a real
disagreement. The conflicts happen in the desk's local catch-up merge, not in
github.com's merge — which is what makes a `.gitattributes` attribute effective
here, since GitHub ignores it when merging a pull request itself.

## 3. Changes

### 3-1. Merge ledger indexes by union, guard the result ([d627902](https://github.com/qmu/research/commit/d627902))

Adds the union attribute, `scripts/check-workaholic-indexes.sh` behind
`make ledger` (wired into `ci.yml`), the CLAUDE.md convention, and the repaired
index entries.

## 4. Outcome

A desk merging `main` no longer stops on an index. Replaying a real conflict from
this week (branch `d61fc98` merging `main` at `b32d909`) produces 0 conflicts, 24
entries and no duplicates, and `refresh-index.sh` then reports no change. The guard
exits 0 over 4 indexes, and exits 1 naming the file when an entry is dropped or
duplicated.

## 5. Concerns

### The stories index has no generator, so union order is insertion order

- **Severity:** low
- **Description:** `stories/index.md` is report-maintained because its per-entry description exists nowhere else, so after a union merge the entries sit in each side's insertion order rather than strict reverse-chronological order, and nothing repairs it (see [d627902](https://github.com/qmu/research/commit/d627902) in `scripts/check-workaholic-indexes.sh`)
- **How to Fix:** Upstream in `qmu/workaholic`: add a `summary:` key to the Story frontmatter carrying the text `/report` writes into the index today, and let `refresh-index.sh` own the stories region like every other area — then order is deterministic and any merge is repaired by regeneration

## 6. Successful Development Patterns

- Write the guard before the silencer: the check was built first and immediately found 13 entries missing from indexes nobody had noticed drifting, so the union attribute landed on a ledger that was already known-good rather than on one whose state was assumed.
- Identity, not prose, is the checkable property of a generated index — comparing link targets against the directory catches every merge artifact without duplicating the description logic that belongs to the generator.
