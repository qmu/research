## 1. Overview

The record that renders the published LLM comparison tables existed **only** as a gitignored, machine-local `.real.data.json` on one checkout. A fresh worktree therefore found no previous record, `mergeConfigs` never ran, and a Gemini-scoped sweep's 12 configs became the *whole* record — which would have taken the published speed and accuracy tables from **47 rows to 12**. It was caught by inspection before publishing, not by any check.

**Highlights:**

1. A scoped run with no base now **refuses**, naming both locations it searched and both remedies. "First full run" and "scoped run with no base" are no longer the same code path.
2. The record is **reproducible from the repository** — by folding every committed frame through the existing `mergeConfigs`, not by committing another artifact.
3. `--render-latest` renders that reconstruction, which is what makes its own documented promise ("generate the report anytime from committed history") actually true.
4. The projection into the published pages refuses **any** narrowing, reporting both counts.
5. Measured in this clean worktree: the newest frame alone yields **54** configs; the reconstruction yields **71**.

## 2. Motivation

The runner's merge logic was correct. The defect was in where `previous` came from — and `.gitignore` covers `docs/research-reports/*.real.*` **deliberately**, so "no previous record" is the *normal* state of every fresh worktree, not an anomaly. That is why the failure was systematic rather than a one-off.

The ticket named this the third instance of one root pattern: a gitignored, machine-local file the worktree flow does not carry, silently degrading a run rather than failing it. The generalised rule it drew is the one this change implements — **when absence of an input changes results rather than stopping the run, absence must be reported.**

## 3. Changes

### 3-1. Rebuild the comparison record from frames ([3e49308](https://github.com/qmu/research/commit/3e49308))

Added `reconstructRecord`, `archivesOldestFirst`, `mayWriteWholeRecord` and `isImplausibleNarrowing` to the history domain; wired the committed-frame fallback, the scoped-run refusal and the reconstruction-based `--render-latest` into the comparison runner; added the narrowing guard to the split-topic projection; 15 unit tests. 4 files.

## 4. Outcome

- **`mayWriteWholeRecord(selectorPresent, hasBase, allowPartialRecord)`** — the runner refuses when a selector is set and no base exists. `--allow-partial-record` is the explicit override.
- **`reconstructRecord(framesOldestFirst)`** — replays every frame through `mergeConfigs`, reusing the exact policy incremental runs already apply: carry forward untouched configs, never let `error`/`fixtured` overwrite `measured`.
- **`loadPreviousCore` falls back** to the reconstruction when the local artifact is absent, and says so.
- **`isImplausibleNarrowing(previous, next)`** — the projection refuses on any decrease, printing both counts and pointing at `--render-latest` as the rebuild path. `--allow-narrowing` overrides.

## 6. Concerns

- **Verification is by pure predicate, not end to end, and deliberately so.** The live scoped path needs provider credentials and this worktree carries a real `packages/tech/.env`, so exercising the refusal branch would have made **paid API calls**. The ticket's Quality Gate had already decided hermetic script-level verification; the three decisions were extracted as pure functions and covered by unit tests. The reproducibility criterion *was* verified for real, because that path is keyless.
- **The narrowing guard refuses on any decrease, not a threshold.** The ticket said "dramatically fewer"; any decrease is stricter. A deliberate model retirement will now need `--allow-narrowing`. That seemed the right side to err on given a silent 47 → 12 rewrite is the failure being prevented, but it is a judgment call a reviewer may want to revisit.
- **`HISTORY_KEEP = 20` bounds the reconstruction.** Pruning old archives eventually drops configs that no later frame re-measured. Not a problem at 5 frames, but the reconstruction is only as complete as the retained frames — the retention policy is now load-bearing for reproducibility in a way it was not before.
- **The published pages were not regenerated here.** This branch fixes the machinery; it does not re-render the articles from the 71-config reconstruction. That is a separate, reviewable change.

## 7. Successful Development Patterns

- **Reuse the existing policy instead of writing a second one.** Reconstruction is `mergeConfigs` replayed over the archive — same operation, same data. No new merge semantics, no second artifact to keep in sync, and the downgrade guard comes along for free, so a reconstruction cannot be corrupted by a later error frame.
- **Extract the decision when the path is unreachable in a test.** The refusal branch sits behind credentials; making it a pure predicate over three booleans moved it from "asserted in prose" to "machine-checked", which is what the Quality Gate actually asked for.
- **Distinguish absence-that-stops from absence-that-changes-results.** `--only-errored` already refused without a base; the other selectors did not, and that asymmetry was the entire bug.
