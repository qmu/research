## 1. Overview

Both remaining backlog tickets route their fix to `qmu/workaholic` through `/fb`, and both
have been re-attempted for weeks against a blocker recorded as this container's GitHub scope.
This branch measures two further blocks that scope cannot remove, and corrects the option set
the tickets had been offering the developer.

**Highlights:**

1. The `/fb` crossing requires a non-skippable `AskUserQuestion`, so no unattended tick reaches it at any scope.
2. Each ticket's "verbatim, one copy-paste" payload is refused by `check-outbound-body.sh` for naming this repository.
3. All four plugin digests are unchanged at 1.0.189 — the third release to pass over the defect.

## 2. Motivation

The fifth re-check on `20260813035140` argued that granting this environment access to
`qmu/workaholic` was "the only option that converts these ticks into progress, because the
payload is already written". Both halves of that sentence are wrong, and every future tick
would have re-derived the same dead end before finding out. Recording why costs one PR-unit
once; not recording it costs one per tick indefinitely.

## 3. Changes

### 3-1. Record why `/fb` cannot file these two defects ([c6f0571](https://github.com/qmu/research/commit/c6f0571))

Appended one re-check entry to each ticket: the 1.0.189 probe rows, the contract reading that
makes the crossing attended-only, and the backstop refusal measured against each ticket's own
prepared payload. The corrected option set is written once, in the older ticket, and referenced
from the newer one rather than duplicated.

## 4. Outcome

Both tickets stay `blocked` and stay in `todo/`. What changed is that the block is now stated
correctly: it is two developer-reserved acts — the crossing's verbatim confirmation and the
masking judgement — not a container setting, so the decision in front of the developer is to
run `/fb` attended or to icebox the tickets.

## 5. Concerns

### The queue keeps offering an unattended routine work no unattended run can finish

- **Severity:** moderate
- **Description:** Both tickets terminate in a `/fb` crossing, whose verbatim confirmation is an `AskUserQuestion` that `/implement` may never issue; the survey has no way to see that, so it re-offers them every tick (see [c6f0571](https://github.com/qmu/research/commit/c6f0571) in `.workaholic/tickets/todo/`)
- **How to Fix:** Icebox both tickets until a developer files them attended, or give a ticket a way to declare that its remaining steps are attended-only so the unattended survey can drop it the way `verification_handoff:` drops an unverifiable one
