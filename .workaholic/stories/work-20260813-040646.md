## 1. Overview

The generational gate tests spread while the article claims a difference of
means, so no trial count can resolve a suppressed direction. This branch
measures what the matching statistic would change — much less than feared.

**Highlights:**

1. `se_diff` as a pure module, with the narrowing property the current gate lacks pinned by tests
2. Two label changes across every committed frame, both restoring a withheld direction
3. Five trials per side would resolve three Opus 4.8 → Opus 5 directions

## 2. Motivation

ADR 0008's gate was right to stop a bare percentage over three trials being
published as a generational finding — the same configuration re-swept hours
apart moved throughput by up to 88%. But its threshold is built from the sample
standard deviation, which does not shrink as trials are added, so raising
`--trials` buys nothing and lowering the bar restores the original defect. The
project has no lever, and that is what this branch is about.

## 3. Changes

### 3-1. The generational gate tests dispersion, not whether the two means differ ([186249e](https://github.com/qmu/research/commit/186249e))

Adds `generational-precision.ts` (standard error, both bands, and the trials a
difference would need), the `generational-precision` analyzer over any frame
artifact, and ADR 0011 carrying the measured label-diff and
trials-to-resolve tables. The published gate is unchanged.

## 4. Outcome

The decision now has evidence instead of intuition: adopting the standard-error
band costs two restored directions in one superseded frame and loses none.

## 5. Concerns

### The 2× band is a proposal, not a derived threshold

- **Severity:** moderate
- **Description:** 2.0 is the conventional ~95% two-sided interval, not a value fitted to this instrument's replication data, and the ticket's own policy note asks that any new threshold be justified against that recorded data (see [186249e](https://github.com/qmu/research/commit/186249e) in `docs/adr/0011-standard-error-for-generational-directions.md`)
- **How to Fix:** Run the analyzer at `--band 1.5` and `--band 2.5` over the same frames before ruling, so the choice is made against three measured consequences rather than one

### Nearly half the generational metrics cannot be judged at all

- **Severity:** moderate
- **Description:** 27 of 63 metrics in the 2026-08-04 frame are `undecidable` because a side has `n < 2` — accuracy metrics are largely measured once — so the statistic is silent exactly where the article still prints a direction (see [186249e](https://github.com/qmu/research/commit/186249e) in `packages/tech/src/entrypoints/analyze-generational-precision.ts`)
- **How to Fix:** Decide separately what a single-trial metric may assert; neither gate currently distinguishes "measured once" from "measured and stable"

### The analyzer reads history frames because the current one is fixtured

- **Severity:** low
- **Description:** `docs/research-reports/llm-model-comparison.data.json` is entirely `fixtured`, so the default invocation compares nothing and the real evidence is only in `history/*.data.json.gz` (see [186249e](https://github.com/qmu/research/commit/186249e))
- **How to Fix:** Leave as is — the default is honest about finding nothing — but pass `--frame` explicitly when the answer matters

## 6. Successful Development Patterns

- Computing the alternative rule *beside* the published one, and reporting the diff, turned a "which threshold is right" argument into a table — the decision stayed the owner's, but it stopped being a matter of opinion.
- `trialsToResolve` is checked against the band it predicts at `n` and at `n − 1`, so the closed-form derivation is verified by the thing it claims to predict rather than by restating the algebra.
