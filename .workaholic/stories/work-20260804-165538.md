## 1. Overview

One real Claude head-to-head sweep, and the two measurement defects it exposed.

The sweep ran as specified and cost **$8.84** of its approved $15 ceiling. It
then produced a generational table asserting that Opus 5 improved **+785%** on
throughput while its total response time **regressed 127%** — two contradicting
directions from the same three trials. Publication stopped there. The metric was
wrong, and so was the first-token time feeding the row beneath it.

Both are now fixed, the committed history is converted, and the published pages
are re-derived. **No re-measurement was needed for any of it.**

## 2. Motivation

Anthropic shipped Opus 5 at the same list price as the Opus 4.8 it replaces. The
mission wanted the published article to state the generational delta with
measured numbers rather than a `not-measured` label, run as a controlled
head-to-head where only the model ids differ.

## 3. Changes

**The sweep.** 13/13 Claude configs measured live at
`2026-08-04T07:56:39.415Z`, zero errored among them; the 6 errored rows in the
record are pre-existing `bedrock-*` entitlement-lag entries carried forward. The
desk had no local artifact — the normal state of a fresh worktree, since
`*.real.data.json` is gitignored — so the instrument reconstructed a 71-config
base from the committed frames. That is the reproducible path and it makes the
carried-forward non-Claude rows auditable; its cost is that 0/13 configs
warm-started and the estimate rose from $5.80 to $8.84.

**Throughput is now end to end** (`outputTokens / totalMs`), per the owner's
decision, recorded as **ADR 0009**. The retired definition divided by the window
*after* first token, so a model that shifts work into pre-emission reasoning
measured as faster the more it thought; one Opus 5 `max` trial divided 2048
tokens by a 948 ms window and reported 2160 tok/s. The function now takes **no**
time-to-first-token parameter — accepting one is what let a missing measurement
change the denominator, so removing it makes that class of error
unrepresentable. Renamed "sustained throughput" → "output throughput".

**An uncaptured first-token time is now `null`, not 0.** All six adapters
initialised `ttftMs` to 0 and used 0 as the "not captured" sentinel, so a
non-measurement was averaged in as a fast one: Opus 5 `high` published
10459 ± 10048 ms over trials of 19922, **0** and 11456 ms.

**Committed history is converted on read, not migrated.** Archives stay exactly
as written; the current definitions are applied when a record is interpreted, so
a future change needs no migration either. Records declare their definition.

## 4. Outcome

All seven of the sweep ticket's acceptance criteria are met, and all five of the
defect ticket's.

**Direction changes — the material output.** 7 of 9 generational throughput
directions changed:

| pair | effort | before → after |
| ---- | ------ | -------------- |
| Opus 4.8 → Opus 5 | high | indistinguishable → improved |
| Opus 4.8 → Opus 5 | max | indistinguishable → improved |
| Gemini 3.5 → 3.6 Flash | low, medium, high | indistinguishable → **regressed** |
| Gemini 3.1 → 3.5 Flash-Lite | low | improved → **regressed** |
| Gemini 3.1 → 3.5 Flash-Lite | medium | indistinguishable → improved |

Removing the TTFT zeros additionally moved TTFT rows from `indistinguishable` to
`regressed`. **Three of these land on the Gemini mission**, which is awaiting
publish; its article will differ from what was reviewed.

Opus 4.8 → Opus 5 `low` stays `improved` but at **+78%**, not +785% — now
coherent with its regressed total response time, because Opus 5 writes ~4.5× more
tokens in ~2.3× the time. Opus 5 `high` TTFT reads 15689 ± 8297 ms (n=2) and
`max` reads 21751 ms (n=1): an honest sample count instead of a mean over a
non-measurement.

**Converting the history cost nothing.** Where the raw speed-call token count
survives the rate recomputes exactly; where it does not, the retired rate
rescales exactly — old rate × (generation window / total window), with the token
count cancelling. All 12 otherwise-unrecomputable trials converted that way, and
47 archived trials had their `ttftMs: 0` reinterpreted.

## 5. Historical Analysis

The retired definition was adopted on 2026-07-05 with a real argument — the
original end-to-end rate was round-trip latency in disguise — and no ADR. It was
load-bearing on what published articles assert, and it was recorded only as a
comment. ADR 0009 now records both sides, because the trade-off is genuine: the
accepted cost of going back to end-to-end is that a model which thinks long and
emits quickly reads as slow, and its emission speed is no longer visible in this
number.

## 6. Concerns

- **A sequencing error cost a translation pass (~$7.20).** The Japanese pages
  were translated *before* the TTFT fix changed the numbers they contain, so both
  had to be regenerated. The accuracy page was affected too, not just speed,
  because the generational section appears in both. Translate after every
  number-changing change has landed.
- **The regenerated Japanese pages drift in terminology within a page** — the
  accuracy article names one field `総合判定` nine times and `総合評価` once. The
  numbers are correct (all nine verdict lines verified against the English figure
  by figure); the labels vary. Filed as
  `20260805120000-japanese-translation-terminology-drifts-within-a-page.md`
  rather than re-translated, since a third pass costs money and would drift
  elsewhere. The committed pages are its fixture.
- **Uncaptured first-token times are excluded, not recovered.** Opus 5 `max`
  reports TTFT at n=1. Recovery needs re-measurement.
- **The dispersion-vs-standard-error gate defect (`20260801124500`) is untouched
  and more pressing now.** The gate suppresses *noisy* artifacts; it admitted
  this one because it was tight and systematic. It is the only thing standing
  between a consistent-but-wrong measurement and a published direction.
- **Mission criterion 4 is not met and must not be marked so.** The publish flow
  runs on `/ship`, after merge. `archive.sh` auto-checked it from the ticket id;
  it has been unchecked. It is also blocked by the open `/request` backstop
  defect (`20260801230000`), which structurally cannot deliver this repository's
  publish ticket.

## 7. Successful Development Patterns

- **Stop at the contradiction.** The defect was caught because two rows of the
  same table disagreed. A published number that contradicts its neighbour is a
  stronger signal than either number alone — worth checking for deliberately
  before shipping a generated table.
- **Invert the old formula instead of paying to re-measure.** The retired rate
  times (generation window / total window) is the end-to-end rate, with the token
  count cancelling. A definition change over committed history is often
  arithmetic, not a re-run.
- **Convert at every reader, and make the state self-describing.** Fixing one
  entrypoint left the split publishing retired numbers next to a corrected
  report. Artifacts now declare their definition, and projections carry it —
  because a projection that *dropped* it would be rescaled a second time and
  silently shrink correct rates.
- **Convert per frame, before folding.** Fold-then-convert breaks the moment
  frames declare different definitions, which is the state the next sweep creates.
- **A sentinel that is a valid value will be counted as one.** `ttftMs: 0` meant
  "not captured" and entered the mean. `null` is excluded by the aggregate; 0 was
  not. Removing the parameter entirely beat guarding it.
- **Commit before mutation-testing.** A harness that restores with
  `git checkout --` destroyed uncommitted work under test earlier in this
  session.
