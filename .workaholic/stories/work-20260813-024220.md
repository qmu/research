## 1. Overview

The repository publishes comparison research only. This branch proposes a
second research type — a wide-shallow sustainability and security assessment
of the components already depended on — and stops at the guideline's gate.

**Highlights:**

1. `docs/oss-foundation-proposal.md` — the five elements, with four decisions left explicitly open
2. ADR 0010 — the four-section article cap, status `proposed`
3. 666 distinct npm packages measured across three committed lockfiles: the argument for the cap

## 2. Motivation

The organization needs standing due diligence — is each depended-on component
still maintained, and what is its vulnerability history — and that question has
a different shape from every published topic. Comparison research reads a
handful of candidates across many axes; this reads hundreds of already-chosen
components across a few. The 7-section article does not survive that count, and
neither does cutting coverage to keep it: 20 of 666 answers nothing.

## 5. Concerns

### The proposal's cost figure is an extrapolation, not a measured estimate

- **Severity:** moderate
- **Description:** The guideline requires the cost element come from the topic's own `--estimate` path, which cannot run before the topic exists — so the $0.20–$6 range in `docs/oss-foundation-proposal.md` §4 is a token-cost extrapolation (see [320a74f](https://github.com/qmu/research/commit/320a74f) in `docs/oss-foundation-proposal.md`)
- **How to Fix:** Treat the ceiling as provisional; run `npm run research:translate-report -- <topic> --estimate` as the first action after scaffolding and correct the recorded `costPerRun` before the first full-catalog translation

### A second article outline enters a codebase that has enforced exactly one

- **Severity:** moderate
- **Description:** ADR 0010 requires `article-outline.ts` to become outline-per-type; the existing 7-section enforcement is global, and a stretched single outline is how the four-section cap gets lost (see [320a74f](https://github.com/qmu/research/commit/320a74f) in `docs/adr/0010-wide-shallow-per-dependency-assessment-articles.md`)
- **How to Fix:** Make the cap a test at the same tier as the 7-section check when scaffolding, not a review note

### Catalog coverage will be partial for a long time

- **Severity:** low
- **Description:** Stratum-A-first rollout means the section publishes a fraction of the 666-package surface for several surveys, and an index that lists only what exists implies whole-catalog coverage (see [320a74f](https://github.com/qmu/research/commit/320a74f) in `docs/oss-foundation-proposal.md`)
- **How to Fix:** Publish the covered/uncovered counts on the index page as a catalog-level series from the first survey
