## 1. Overview

`scripts/publish-research.sh copy` writes into a directory it **shares with hand-authored prose** on qmu-co-jp. At least one exported article had since been given an authoritative descriptive body downstream — and every re-run replaced it without a word. This branch gives the exporter an ownership boundary and states it in the tool rather than leaving it to memory.

**Highlights:**

1. A committed ledger (`scripts/publish-ledger.tsv`) records the sha256 of what the exporter last emitted per destination. A destination the exporter cannot prove it wrote is **skipped, loudly**, naming the file and the reason — and the run continues with the rest.
2. `--force` is the explicit override; `--dry-run` refuses too and writes nothing.
3. The ownership boundary is written into the script header: never authored downstream → this repo wins; authored downstream → qmu-co-jp wins.
4. `make publish-guard` (`scripts/check-publish-guard.sh`, 9 assertions) runs in CI. **Mutation-tested**: neutralising the check fails 5 of them, including the ticket's own scenario verbatim.
5. **The ledger was seeded from the real downstream state** — and the seeding is itself the guard's first finding (section 5).

## 2. Motivation

A deterministic generator that shares a destination with hand-authored content has an ownership question, and the only durable place to answer it is the tool. Left in memory, the answer survives exactly as long as the person who remembers it — and the failure mode is silent, irreversible, and invisible in this repo's own diff, because the loss happens in a sibling checkout.

## 3. Changes

### 3-1. Guard the exporter against downstream overwrite ([0cfb3c2](https://github.com/qmu/research/commit/0cfb3c2))

Added the ledger, the pre-write ownership check, `--force`, the header statement of the boundary, the `check-publish-guard.sh` test, the `make publish-guard` target and its CI step, and the seeded ledger. 6 files.

## 4. Outcome

The decision table, applied per destination before any write:

| state | action |
| --- | --- |
| destination missing | copy (nothing to lose) |
| hash matches the ledger | copy (untouched since our emit) |
| hash differs from the ledger | **skip, loudly** |
| no entry, dest **==** source | record and continue (bootstrap) |
| no entry, dest **!=** source | **skip, loudly** |

A marker comment inside the destination was rejected in favour of the sidecar ledger: the destinations are published prose, so a machine marker would be visible on the corporate site.

## 5. Historical Analysis

Seeding the ledger against the live `../qmu-co-jp` split the 35 planned destinations into three groups, and the split is the guard's first real finding:

- **32** are byte-identical to their source → recorded. These are demonstrably this exporter's own emits.
- **1** does not exist downstream yet (`history/image-generation/2026-07-18T15-04-12-341Z/…`) → will be created normally.
- **2** diverge and were **deliberately left unrecorded** so they surface for review:
  - `agent-vm-comparison.md` — its downstream frontmatter carries `provenance: authored-fixture-translation`. **Genuinely authored downstream**; skipping is the correct outcome, and this is the class of file the ticket was filed to protect.
  - `image-generation.md` — **a stale export, not authored prose.** Its downstream copy points at an older frame (`source_commit: 78a9397`, 118 lines) while the source has since been regenerated (175 lines).

That second case is why the skip message states a reason and names *both* remedies instead of asserting the downstream text is authoritative: "diverged" means "we cannot prove it is ours", which is not the same as "someone wrote it by hand".

## 6. Concerns

- **`image-generation.md` will skip at the next `/ship` and wants `--force`.** It is the pending article the image-generation mission is waiting to publish. This is the guard working as designed, but it will look like a failure to whoever runs the next publish if they have not read this. Alternative remedy: record its destination hash in the ledger.
- **Image assets are still copied unconditionally.** `cp -R` over `images/` has no ownership check. The ticket scoped this to article prose, and binary assets have no hand-authored analogue here — but the asymmetry is real and undocumented anywhere but this line.
- **The ledger must be committed after a real publish**, or the next run sees its own emit as diverged. The script prints this reminder on every non-dry run, but nothing enforces it.
- **Touches `Makefile` and `.github/workflows/ci.yml`**, as does the concurrently-driven branch for ticket `20260717130639` (masked `make` targets). Both edits are additive and in different regions; expect a trivial merge, but merge order matters.

## 7. Successful Development Patterns

- **Decide ownership before writing, not after.** The check runs on the destination's bytes prior to `cp`, so there is no window in which the authored text is already gone.
- **Mutation-test the guard.** Neutralising the ownership check fails 5 assertions including `a hand-edited destination was OVERWRITTEN` — the ticket's scenario, reproduced on demand. A guard only observed green proves nothing.
- **Seeding is part of shipping a ledger-based guard.** An empty committed ledger would make all 35 destinations look authored, the first `/ship` would skip everything, and the operator would learn to pass `--force` reflexively — permanently disarming the guard.
- **Split the bootstrap case against the source.** It is the one place this design silently fails in *both* directions; comparing an unrecorded destination against the source resolves it without guessing.
