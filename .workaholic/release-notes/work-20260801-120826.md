# Stop make targets masking non-final package failures

## Summary

Every per-package `make` target discarded the exit status of all packages but the last, so `make test` returned 0 on a tree that failed its own tests — and CI invokes those same targets. All five targets now accumulate status, and a new `make gate` proves it.

## Key Changes

- `install`, `build`, `test`, `lint`, and `format` share one status-accumulating `for_each_package` shape: every package runs, any failure is non-zero, and the failing packages are named.
- Added `scripts/check-make-gate.sh` (`make gate`), asserting raw exit codes with the failure in first, middle, and last position, plus healthy-tree controls.
- `make gate` runs first in `ci.yml`, so a masking regression fails before the gates it would mask.
- `CLAUDE.md`'s "Never verify through make" guidance no longer describes the defect as unfixed.

## Changes

### Added
- `make gate` and `scripts/check-make-gate.sh`, wired as CI's first step.

### Changed
- All five per-package Makefile targets now report failures in any position.
- `CLAUDE.md` verification guidance updated to match the fixed runner.
