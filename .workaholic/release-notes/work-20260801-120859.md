# Add the post-hoc usage-field survey axis to token-metering

## Summary

The token-metering article read as though the topic were input-only, conflating pre-flight prediction (input by necessity) with post-hoc actual usage read back off the response. The second is now an explicit axis, and the framing names both.

## Key Changes

- `domain/usage-survey.ts` carries the axis as pure data plus a pure renderer, with per-row provenance.
- Subjects span all three surface kinds: direct provider APIs, an agent-SDK layer, and the domain-specific case (Perplexity, which bills search separately from tokens).
- Dimensions cover the streaming case with its exact opt-in string, and what the reachable SDK layer does to the figures.
- A test asserts a keyless row may not claim `reported` for any dimension, so the axis cannot be filled in by fabrication.

## Changes

### Added
- The post-hoc usage-field survey axis, its renderer, and its no-fabrication test.

### Changed
- The article introduction names both capabilities and states how they reinforce each other.
