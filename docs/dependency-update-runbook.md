# 依存更新を取り込む手順

依存更新（Dependabot など）を取り込むときに、PR 本文へ結果を残すための共通手順です。操作はすべて `make` 経由で行います（ワークフロー YAML に処理を書きません）。

## 前提

- Node `>=22 <23`、npm `>=10.9 <11`（各 `package.json` の `engines`）。npm のバージョンが違うと lockfile の形式差だけの差分が出ます。
- 失敗の確認には、終了コードをそのまま見ます（`| tail` や `|| true` を付けません）。

## 順序

1. `make install` — 依存を導入する。期待結果: 終了コード 0。
2. `make lockfiles` — 導入で `package.json` や lockfile が書き換わらないことを確認する。期待結果: 書き換えなし。書き換わる場合は宣言された npm で導入し直し、差分をコミットしない。
3. `make build` — 型検査とビルド。期待結果: 終了コード 0。
4. `make test` — 全パッケージのテスト。期待結果: 終了コード 0。`packages/industry` はテストファイルが無いため、その成功は弱い証拠です。
5. `make lint` — 期待結果: 終了コード 0。
6. `make docs` が関係する更新（`docs/` の依存）では、`make a11y` も流す。

## PR 本文に残すもの

- 更新したパッケージと版（from → to）と、対象の Dependabot PR（owner/repo#番号）。
- 上の各コマンドの実行結果（成功・失敗・未実行）。未実行のものは未実行と書く。
- `node -v` と `npm -v`。
- 重複確認: 同じ変更を扱う開いている PR の有無。
